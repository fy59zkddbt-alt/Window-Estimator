# Window Estimator — UX + Pricing Specification v1.2

## 1. Назначение продукта

Window Estimator — специализированный mobile-first веб-инструмент для замерщиков окон. Основная среда использования — телефон непосредственно на объекте.

**Быстрый замер → мгновенный расчёт → проверка → понятное предложение клиенту → изображение/PDF.**

UX-принципы:

- Минимум ручного ввода и вычислений в голове.
- Схема конструкции — центральный элемент рабочего интерфейса.
- Частые параметры видны сразу; редкие скрыты, но их наличие визуально очевидно.
- Цена пересчитывается автоматически; отдельной кнопки «Рассчитать» нет.
- Замерщик видит добавленные позиции и стоимость, клиент — понятную конфигурацию.
- Настройки понятны без изучения сложных формул.
- Типичный заказ экспортируется в 1–2 вертикальных изображения.

## 2. Основной flow и позиции

**Расчёт → Добавление позиции → Редактор позиции → Расчёт → Итог → Клиентское предложение → Изображение/PDF.**

Виды замеров: Window, Balcony, WindowFinish. ПВХ и алюминий — материалы, не виды замеров. Additional Work — дополнительная работа.

Bottom sheet «+ Добавить» предлагает: **Окно**, **Балкон / остекление**, **Отделка окна**, **Дополнительная работа**. Отдельный экран выбора не нужен.

Отделка самостоятельна: может существовать без нового окна или создаваться действием **Добавить отделку** из окна. Передаются помещение, ширина и высота. Глубина всегда вводится отдельным фактическим замером.

## 3. Главный экран «Расчёт»

Пустое состояние: заголовок **Расчёт**, необязательное название объекта и основное действие **+ Добавить изделие**. Пустой экран не перегружается другими блоками.

После добавления показываются карточки:

- Окно: помещение, мини-схема, размер, профиль, фурнитура, нестандартный цвет, изделие, монтаж, итог.
- Балкон: помещение, общая схема, форма, материал, профиль / система, фурнитура, площадь, изделие, монтаж, итог.
- Отделка: помещение, внутренняя / наружная, размер, фактическая глубина, материалы и **Отделка под ключ — X ₽**. Внутренняя калькуляция не раскрывается.
- Дополнительные работы: компактный список названий и клиентских сумм.

Изделие и монтаж всегда показываются раздельно.

Тап по карточке открывает редактор. Меню `⋮`: **Дублировать**, **Удалить**, для обычного окна и балконного блока — **Добавить отделку**. Дублированная позиция сразу открывается в редакторе.

Нижняя фиксированная панель: итог, **+ Добавить**, **К результату**. При неопределённой цене достоверный общий итог не показывается.

## 4. Редактор окна

Тип конструкции: **1 створка | 2 створки | 3 створки | Балконный блок**.
Отдельная сущность «Дверь» не требуется: одиночная дверь задаётся одностворчатой конструкцией с соответствующими размерами и параметрами.

Порядок экрана: помещение → тип → крупная интерактивная схема → общие размеры → размеры секций → открывания через схему → комплектация → дополнительные параметры → цена → сохранение.

Обычное окно задаётся общей шириной и высотой. После ввода общей ширины секции делятся поровну: 1400 мм → 700 / 700; 1800 мм → 600 / 600 / 600.

### Автоширины

- Изменение секции компенсируется следующей секцией справа.
- Последняя правая секция напрямую не редактируется и замыкает общую ширину.
- Если соседняя секция становится недопустимой, изменение отклоняется.
- При изменении общей ширины секции снова делятся поровну.
- Сумма ширин секций равна общей ширине; ручной контроль суммы не требуется.

### Открывания и комплектация

Открывание задаётся тапом по схеме, без отдельного технического списка секций.
Для ПВХ: **Глухая | Поворотная | Поворотно-откидная**. Для активной створки выбираются **Петли слева | Петли справа** и совместимая фурнитура. Для алюминия действуют правила раздела 6.

Постоянно видны **Профиль**, **Фурнитура**, **Цвет**.
Редкие параметры находятся в **Дополнительные параметры ›** с подсказкой «Расширители, соединители и другие редкие настройки».
Раскрываемые блоки имеют явный маркер `›`, `⌄` или аналогичный.

Sticky-панель: **Изделие — X ₽**, **Монтаж — Y ₽**, **Итого — Z ₽**, **Сохранить**.

## 5. Балконный блок

Балконный блок — вариант WindowMeasurement: `kind=Window`, `windowType=balconyBlock`, не самостоятельный вид замера и не BalconyMeasurement.

В UI вводятся:

- общая ширина оконной части;
- ширина двери;
- высота окна;
- высота двери.

Оконная часть делится на 1–2 секции по правилам автоширин. Дверь редактируется тапом по схеме.

Для действия **Добавить отделку**:

```text
width = суммарная ширина оконной части/окон + ширина двери
height = высота двери
```

Глубина всегда вводится отдельным фактическим замером.

## 6. Балкон / остекление и алюминий

Форма: **Прямой | Г-образный | П-образный**. Материал: **ПВХ | Алюминий**.

Для каждой алюминиевой плоскости выбирается механизм **Раздвижное (sliding) | Распашное (swing)**. В одной плоскости механизмы не смешиваются.

- sliding: допустимы fixed и sliding.
- swing в MVP: допустимы fixed и turn.
- tilt_turn для алюминия не используется.

У алюминиевой системы отдельно настраиваются activity markup для sliding и swing. Механизм влияет на схему, допустимые створки и расчёт активной площади по соответствующей надбавке.

Для П-образного балкона плоскости: **Левая | Фасад | Правая**. На телефоне редактируется одна плоскость за раз; общая схема остаётся видимой и служит навигацией.

У каждой плоскости свои ширина и высота. Высота следующей наследуется от предыдущей и может быть изменена. Количество секций задаётся контролом `− / +`; секции распределяются и редактируются по правилам автоширин. Открывания задаются на схеме.

ПВХ допускает fixed, turn, tilt_turn.

### Остекление в пол

Свойство конкретной плоскости: **Остекление в пол — Да/Нет**.
При включении выбирается нижнее заполнение **Стекло | Сэндвич**.
Высота нижней части всегда вводится пользователем как фактический размер. Автоматический default не используется.

Комплектация: профиль / система, фурнитура при применимости, цвет, дополнительные параметры.
Цена: изделие, монтаж, итог отдельными строками.

## 7. Настройки остекления

Главная сущность каталога — профиль / система. Фурнитура хранится отдельным каталогом; пользователь может переименовать нейтральные варианты в реальные системы.

Карточка профиля содержит название, базовую цену ₽/м², доступную фурнитуру, надбавку активности по каждой фурнитуре, цвет / ламинацию, расширители / соединители и наценку изделия.

Надбавка активной створки — свойство комбинации **Profile + Hardware**. Одна глобальная activity markup для всего профиля запрещена. При разной фурнитуре в одном изделии activity рассчитывается отдельно по соответствующим активным площадям.

Каждая процентная настройка поясняет базу начисления. Формула по умолчанию не показывается.

Значения по умолчанию: профиль ПВХ, фурнитура, цвет, материал остекления. Стандартная комплектация не требует повторного выбора для каждого замера.

### Расширители и соединители

Это опциональные параметры конкретного изделия, не Additional Work. Они имеют отдельные процентные надбавки, влияют только на product price и не влияют на installation price.

## 8. Glazing pricing

Площади выражены в м², basePrice — ставка за м².

```text
base =
  totalArea × basePrice

activity =
  Σ(
    activeAreaForHardware
    × basePrice
    × activityPercent(profile, hardware) / 100
  )

color =
  totalArea × basePrice × colorPercent / 100

extensions =
  totalArea × basePrice × extensionPercent / 100

connectors =
  totalArea × basePrice × connectorPercent / 100

productSubtotal =
  base + activity + color + extensions + connectors

productPriceBeforeCommercialRounding =
  productSubtotal × (1 + productMarkupPercent / 100)
```

Activity, color, extensions и connectors считаются независимо от базовой стоимости. Они не начисляются друг на друга и не перемножаются между собой.
productMarkupPercent применяется один раз после их сложения.
Расширители и соединители входят в productSubtotal до общего productMarkupPercent.
Для алюминиевой системы применяются отдельные надбавки активности sliding / swing согласно выбранному механизму плоскости.

### Монтаж остекления

Монтаж хранится отдельно от профилей: **ПВХ — ₽/м²**, **алюминий — ₽/м²**.

```text
installationPriceBeforeCommercialRounding =
  totalArea × installationRateForMaterial
```

Product markup, activity, color, extensions и connectors на монтаж не влияют. Монтаж основных изделий не является Additional Work.

## 9. Отделка окна

Отделка бывает **Внутренняя | Наружная**.

Термины внутренней отделки: **Откосы**, **Подоконник**.
Термины наружной: **Откосы снаружи**, **Отлив**.
Утепление / герметизация оформляются как Additional Work, обычно по погонным метрам; в специальную finishing pricing model они не входят.

Геометрия: ширина окна, высота окна, глубина откоса. При создании из окна ширина и высота передаются автоматически, для блока — по разделу 5.
Глубина — реальный замер; она показывается замерщику и клиенту.

## 10. Подбор ширины материала по глубине откоса

Основной термин — **Подбор ширины материала по глубине откоса**, не «типоразмер».

Для каждого варианта задаются:

- физическая ширина материала;
- максимальная фактическая глубина, до которой его можно использовать;
- закупочная стоимость комплекта материалов за 1 пог. м.

Материал выбирается по фактической глубине. Припуски в выборе ширины не участвуют.
Пример: материал 200 мм допускается до фактической глубины 220 мм; при глубине 210 мм он подходит.
Если варианты допускают глубину только до своей ширины, при 210 мм вариант 200 мм не подходит, а 300 мм подходит.

В настройках доступна проверка: ввод тестовой глубины и показ выбранной физической ширины.
Ручной override разрешён только среди вариантов, физически подходящих по фактической глубине.

Подсказка: «Укажите, какую ширину материала использовать при разных фактических глубинах откоса. Калькулятор сам выберет подходящий вариант по замеру».

## 11. Комплект материалов, припуски и запас

**Комплект материалов на 1 пог. м** — полная закупочная стоимость: основной материал, стартовый профиль, пена, герметик, крепёж, обязательные расходники. Отдельный учёт каждого расходника не требуется.

Подсказка: «Указывайте полную закупочную стоимость материалов, необходимых для выполнения 1 погонного метра отделки. Не копируйте только цену панели из прайса поставщика».

Припуски задаются по виду элемента и добавляются к фактическому замеру для необходимого размера. Например, у подоконника могут быть припуски к глубине +50 мм и длине +100 мм; у отлива — собственные значения.
Припуски не участвуют в выборе ширины и не меняют фактическую установленную длину для работы.

Фиксированный запас **20%** учитывает обрезки и остатки. Запас не является припуском.
В новой finishing-модели purchaseStep не используется. Нельзя одновременно применять старую закупочную кратность и новые 20% как два механизма запаса.

## 12. Оплата монтажника отделки

Используется **базовая оплата за вид работ + ставка за погонный метр для выбранного материала**. Универсальная «минималка» не используется.

Внутренние виды работ: **Откосы**, **Откосы + подоконник**, **Только подоконник**.
Наружные: **Откосы снаружи**, **Откосы снаружи + отлив**, **Только отлив**, если эти сценарии поддерживаются.
Названия соответствуют реальным видам работ, не «3 стороны / 4 стороны».

Зарплата монтажника — часть себестоимости. Для работы используется фактическая установленная длина без припусков и запаса.

## 13. Finishing pricing

Отдельной material markup нет. Используется термин **наценка**, не «маржа».
Количество материала и установленная длина в формуле выражены в погонных метрах.

```text
materialCost =
  Σ(calculatedMaterialQuantity × purchaseCostPerRunningMeter)

materialsWithReserve =
  materialCost × 1.20

installerSalary =
  baseLaborForWorkType
  + Σ(installedLength × installerRatePerRunningMeter)

costBasis =
  materialsWithReserve + installerSalary

finishPriceBeforeCommercialRounding =
  costBasis × (1 + finishMarkupPercent / 100)

clientFinishPrice =
  commercialRound(finishPriceBeforeCommercialRounding)
```

Клиент видит только **Отделка под ключ — X ₽**. Закупочная стоимость, зарплата монтажника, наценка и внутренняя себестоимость клиенту не показываются.

## 14. Additional Works

Используется каталог пользователя и одна pricing-модель:

```text
total = unitPrice × quantity
```

quantity > 0. Положительные дробные количества разрешены.
Необязательная единица измерения: **шт. | п.м. | м² | ед.**
Единица — presentation metadata, не отдельный pricing type.

После добавления работа хранит snapshot цены, а не живую ссылку на текущий каталог.
Примеры: доставка, подъём, демонтаж, вывоз, утепление / герметизация, другое.
Монтаж основных изделий не добавляется как дополнительная работа.

## 15. Коммерческое округление и итог заказа

Настройка **Округлять цену до**: **10 ₽ | 50 ₽ | 100 ₽**. Default — **100 ₽**.
Используется математическое округление к ближайшему шагу. Половина шага для неотрицательных цен округляется вверх.

```text
commercialRound(price) = floor(price / step + 0.5) × step
```

- Внутренняя себестоимость коммерчески не округляется.
- Для окна/балкона отдельно округляется изделие и отдельно монтаж. Итог позиции — сумма этих двух видимых строк.
- Для отделки округляется цена под ключ.
- Для Additional Work округляется клиентская стоимость строки.
- Если unitPrice × quantity даёт долю копейки, сначала математически округляется до ближайшей копейки; половина копейки — вверх.
- Процентная скидка применяется после суммы клиентских строк, затем конечный итог снова округляется к коммерческому шагу.
- fixedFinalPrice, явно введённая пользователем, автоматически не округляется.
- Ручная конечная цена отделки повторно не округляется.

Экран **Итог** служит проверке: изделие / монтаж / итог для остекления; **Отделка под ключ** для отделки; дополнительным работам выделен компактный блок. Здесь применяется скидка. Главное действие — **Показать клиенту**.

## 16. Неопределённая и ручная цена отделки

Если подходящего материала нет, показывается сообщение, например: «Для глубины 420 мм нет подходящего варианта материала».

Позицию можно сохранить в Calculation со статусом **Цена требует уточнения**:

- замер не теряется;
- достоверный общий итог отсутствует;
- Client View / Image / PDF блокируются.

Пользователь может добавить подходящий вариант материала или ввести ручную конечную коммерческую цену отделки.

Ручная цена:

- уже является конечной коммерческой ценой;
- должна быть > 0;
- не округляется повторно;
- не создаёт фиктивную себестоимость.

После существенного изменения геометрии, типа отделки, материала или состава работ ручная цена должна быть сброшена либо требовать повторного подтверждения.
Это отдельный override, не Calculation.fixedFinalPrice.

## 17. Быстро / Точный расчёт

Это одна configuration model и один pricing engine.
**Быстро** — сокращённое UI-представление; **Точный расчёт** — полное представление тех же данных.

Переключение режима:

- не меняет цену;
- не меняет configuration;
- не сбрасывает скрытые значения.

Не использовать старую Simple/Advanced pricing semantics и названия «Базовый / Продвинутый».

## 18. Starter configuration и подтверждение примерных цен

После регистрации каталог не пустой. Присутствуют:

- **Стандартный ПВХ 70 мм**;
- фурнитура **Стандарт**;
- фурнитура **Премиум**;
- одна примерная алюминиевая система;
- **Сэндвич-панель**;
- **Подоконник Стандарт**;
- **Подоконник Премиум**;
- необходимые примерные монтажные и labor-настройки.

Заполнены базовая цена, надбавки активности, монтаж, цвет / стандартная комплектация, подбор ширины, припуски, оплата монтажника и коммерческие наценки. Запас отделки — фиксированные 20%. Оба режима показывают одинаковую цену.

Все стартовые коммерческие значения маркируются **Примерные цены**.
До подтверждения показывается ненавязчивое предупреждение:

> Используются примерные цены. Проверьте настройки перед расчётом для клиента.

Действие — **Проверить цены**.

Пользователь один раз явно подтверждает, что проверил цены: pricesConfirmed=true. После этого предупреждение исчезает.
Обычный Save не считается подтверждением. Последующее обычное редактирование цен не сбрасывает подтверждение.
pricesConfirmed=false снова устанавливается только при явном восстановлении starter/example configuration или создании новой конфигурации из примера.

**starter/example configuration не должна автоматически заменять уже настроенный пользовательский каталог.**

## 19. Onboarding

Короткий onboarding без длинного тура.
При первом входе показывается готовый каталог: «Мы уже добавили примерные настройки. Измените их под свои цены или начните с готового шаблона».

Минимальный путь: профиль → фурнитура → монтаж → отделка → подтвердить цены.

Первый замер сопровождается тремя подсказками:

1. «Нажимайте на створки прямо на схеме, чтобы задавать открывание и петли».
2. «Введите общий размер. Секции будут рассчитаны автоматически. При изменении одной секции соседняя справа скорректируется сама».
3. «После расчёта нажмите “Показать клиенту”, чтобы получить готовое предложение со схемами и ценами».

Действие — **Начать первый расчёт**.

## 20. Клиентское предложение

Отдельный presentation-mode без редактирования, настроек, внутренних формул, себестоимости и технических коэффициентов.

- Окно: помещение, схема, общий размер, ключевые размеры секций, открывания, профиль, фурнитура, цвет, изделие, монтаж, итог.
- Балкон: общая схема, плоскости, конфигурация, материал, профиль, фурнитура / система, площадь, «в пол» при использовании, изделие, монтаж, итог.
- Отделка: внутренняя / наружная, размер окна, фактическая глубина откоса, материалы, цена под ключ. Утепление / герметизация показываются как Additional Work при использовании.

## 21. Proposal View Model и экспорт

Существующий ProposalDocument — основа целевого Proposal View Model. Его нужно расширять, не создавать три независимые бизнес-модели.
Из одного DTO строятся **Client View**, **Image Export**, **PDF**. Renderer не рассчитывает цену.

Основной быстрый формат — изображение; PDF — формальный дополнительный формат.
Изображение использует отдельную верстку клиентского предложения, не screenshot рабочего UI.

1–2 вертикальных изображения — цель для типичного заказа, не абсолютное ограничение.
Обычные карточки не разрываются: если не помещаются, переносятся целиком.
Большой балкон допускается логически разделить по плоскостям.
Нельзя уменьшать документ до нечитаемого размера ради лимита в две страницы.

В конце предложения: дополнительные работы, скидка, итог, срок, гарантия, название исполнителя, телефон, мессенджер.
В MVP используются текстовые данные исполнителя без логотипа.

## 22. Ошибки и каталог

Незаполненный обязательный размер подсвечивается; при сохранении показывается конкретная ошибка, например «Укажите высоту окна».
В нормальном flow сумма секций сохраняется автоматически. Некорректная сумма из старых данных / миграции блокирует сохранение.

Профили и материалы, используемые в существующих расчётах, не удаляются физически. Действие — **Скрыть / больше не использовать**. Старые расчёты сохраняют значение, в новых скрытая позиция не предлагается.

## 23. Архитектурные и конфигурационные invariants

Сохраняются React + TypeScript + Vite, Supabase, сервер как источник истины subscription / entitlement, облачные настройки, локальный текущий расчёт и локальное формирование результата. Серверной истории КП и замеров нет.

Geometry и pricing независимы от Auth и доступа. UI отображает результаты engine. Форматы предложения используют единый DTO и не содержат самостоятельной бизнес-логики расчёта цен.

Glazing Configuration содержит профили, каталог фурнитуры, Profile × Hardware activity markup, отдельные алюминиевые sliding / swing markup, цвет / ламинацию, расширители / соединители, product markup, отдельные монтажные ставки и defaults.

Finishing Configuration содержит внутреннюю / наружную отделку, материалы, физические ширины, максимальную допустимую фактическую глубину, закупочную стоимость комплекта за погонный метр, фиксированный запас 20%, базовую оплату по виду работ, ставки монтажника по материалу, припуски, finish markup, округление, starter configuration и pricesConfirmed. Быстро / Точный расчёт — представления одной конфигурации.

Proposal Configuration содержит данные исполнителя, телефон, мессенджер, срок и гарантию.

## 24. Legacy / transition

Продукт ещё не запущен публично. Реальных пользовательских Calculations, ради которых нужен постоянный legacy pricing engine, нет.
Допустим controlled reset / migration calculator-specific dev data. Поддержка старой pricing semantics ради development-данных не требуется.

Нельзя затрагивать:

- Auth;
- ownership/isolation;
- session;
- trusted devices;
- entitlement;
- subscription;
- billing/payment;
- cloud revision/conflict protection.

Запрещены `database.delete()`, `localStorage.clear()` и массовый сброс всех пользовательских settings.

## 25. Что сознательно не входит

- CRM;
- серверная история клиентов;
- серверное хранение КП;
- склад;
- учёт каждого расходника;
- зарплатный модуль;
- бухгалтерия;
- закупочные заявки;
- конструктор дизайна КП;
- сложная ролевая модель;
- корпоративные подписки на несколько сотрудников;
- логотип в MVP.
