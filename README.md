# Window Estimator

## Скидка и итоговая цена

На экране сметы после subtotal доступен блок «Скидка / Итоговая цена»: без скидки, скидка 0–100% или фиксированная итоговая цена. Кнопка «Применить и сохранить» сохраняет настройку внутри Calculation. Скидка охватывает все замеры и дополнительные работы заказа.

Процент: скидка = round(subtotalMinor × percent / 100), итог = subtotalMinor − скидка. Округляется только скидка, один раз до копейки (половина вверх). Fixed: скидка = subtotalMinor − fixedFinalPriceMinor, итог = fixedFinalPriceMinor. Цена не может быть отрицательной или превышать subtotal.

После add/edit/copy/delete замера или изменения работ фиксированная цена требует подтверждения, даже если сумма не изменилась. В смете видны прежняя цена, новый subtotal и кнопки «Оставить итоговую цену» / «Сбросить». Если прежняя цена выше нового subtotal, оставить её нельзя; можно сбросить или задать меньшую цену. До решения итог не финализирован (finalTotalMinor=null). Процентная скидка пересчитывается автоматически; изменения данных клиента не требуют подтверждения.

Состояние: `discount = {mode: 'none'} | {mode: 'percent', discountPercent} | {mode: 'fixedFinalPrice', fixedFinalPriceMinor, confirmation, confirmedSubtotalMinor}`. Расчёт находится в application/estimate, движки цен замеров остаются независимыми. IndexedDB остаётся v3; старые записи без discount читаются как none без автоматической перезаписи. Проверки: `tests/discount.test.ts`.

## Балкон

«Добавить замер → Балкон» открывает отдельный редактор straight/L/U. L позволяет выбрать левую или правую сторону; U содержит левую, фасадную и правую плоскости. Это самостоятельный BalconyMeasurement, а балконный блок остаётся вариантом Window.

Каждая плоскость имеет ID, название/позицию, ширину, высоту, 1–8 секций и ярусность. При первом вводе ширины секции создаются равными; смена количества создаёт заново равные глухие секции. Далее ширины редактируются независимо. Изменение общей ширины не исправляет секции; есть явная кнопка распределения. Несогласованная сумма блокирует цену и сохранение.

Для twoLevel вводится высота нижнего яруса от низа. Нижние секции повторяют ширины верхних, всегда глухие, с заполнением glass или sandwich. ПВХ поддерживает fixed/turn/tilt_turn с фурнитурой и петлями активных секций; алюминий — fixed/sliding без PVC-петель и фурнитуры.

Площадь балкона — сумма площадей плоскостей. Активная площадь включает только активные верхние секции (включая sliding). Площадь sandwich возвращается отдельно; пока он оценивается по общей ставке остекления без специальной поправки. Формула остекления остаётся в общем Pricing Engine. Эскизы показывают плоскости отдельно в реальных пропорциях, без перспективной 3D-модели.

Редактирование, копирование, удаление, работы замера/заказа и смета используют общий Calculation. Копии независимы. IndexedDB остаётся v3; старые расчёты не переписываются и не требуют новой миграции.

Проверки Balcony: `tests/balcony.test.ts`, SVG — `tests/preview.test.tsx`. Запуск всех проверок: `pnpm test`, `pnpm run typecheck`, `pnpm run build`.

## Дополнительные работы

В редакторах окна и отделки можно добавить, изменить и удалить работы замера. Название обязательно, цена вводится в рублях (до двух десятичных знаков), хранится в целых копейках. Нулевая цена допустима. Работы показываются внутри карточки замера в составе расчёта и смете.

После списка замеров расположен редактор «Дополнительные работы по заказу». Его изменения применяются кнопкой «Сохранить работы по заказу». Работы замера сохраняются вместе с замером.

Общая модель: `AdditionalWork { id: string; name: string; priceMinor: number }`. Все виды замеров содержат `additionalWorks[]`, Calculation — `orderAdditionalWorks[]`.

Application складывает `basePriceMinor + additionalWorksTotalMinor = measurementTotalMinor`, затем `measurementsSubtotalMinor + orderWorksTotalMinor = subtotalMinor`. Pricing Engine рассчитывает только базовую стоимость. На дополнительные работы не начисляются наценки профиля или отделочных материалов.

Копирование создаёт независимые работы с новыми ID; изменение копии не меняет оригинал. Удаление замера удаляет только его работы; работы заказа сохраняются.

IndexedDB остаётся v3. Старые записи без новых массивов загружаются с пустыми списками без перезаписи при чтении. Явное сохранение записывает актуальную форму. Миграции v1 → v2 → v3 и резервные старые записи сохранены.

Тесты `tests/additional-works.test.ts` проверяют оба уровня стоимости, copy/edit/delete, безопасный диапазон сумм, повторное открытие БД и старый v3. Количество, единицы, конструктор формул и PDF остаются вне реализации.

Основа локального веб-приложения для оконного замерщика: замер → расчёт → смета → PDF.
Реализован базовый оконный замер: одно-, двух- и трёхстворчатое окно с верхней глухой фрамугой (необязательно), балконный блок с дверью и 1–2 окнами, технический эскиз и текущая цена остекления.

## Архитектура

`domain` не зависит от React, браузера и хранилища. `application/estimate` собирает валидированный замер,
вызывает geometry и Pricing Engine, возвращает MeasurementEstimate со снимком конфигурации. Calculation содержит массив замеров и снимки тарифов по их ID.
`infrastructure/storage` реализует порт CalculationRepository через Dexie.
UI получает репозиторий через props из `main.tsx` и не знает формулу.
Подробные правила и инварианты: [AGENTS.md](AGENTS.md).

Существующая WindowMeasurement — discriminated union по windowType. Для single/double/triple: помещение, название,
общие widthMm/heightMm, material, profileId, lamination, одна плоскость с 1/2/3 нижними секциями и необязательная transom.
Section хранит widthMm и openingType; hingeSide/hardwareId существуют только для turn/tilt_turn.
Высота секций выводится из общих размеров, а не дублируется. WindowInput — вход конструктора этой же модели.
ProfileConfiguration содержит material для проверки совместимости; фурнитура проверяется у каждой активной секции и не создаёт отдельной надбавки.
BalconyMeasurement реализован отдельным сценарием straight/L/U. Дополнительные работы реализованы на уровне замера и заказа. WindowFinishMeasurement реализован как самостоятельный сценарий.

`windowType='balconyBlock'` — вариант той же WindowMeasurement с `kind='Window'`.
Он содержит doorWidthMm/doorHeightMm, windowHeightMm, doorPosition и дверь с общим типом OpeningElement.
В plane.sections — только 1–2 окна с независимыми ширинами. Общих входных габаритов и фрамуги у блока нет.
Geometry.sections для блока содержит окна и дверь в готовом порядке; bounds служит только для эскиза.
Стоимость определяется суммой реальных площадей элементов. Pricing Engine и SVG-рендерер общие для всех типов.

Geometry возвращает totalAreaM2/activeAreaM2, bounds, sections, transom и координаты обозначений открывания.
Начало координат — верхний левый угол, единицы — мм, вид из помещения.
SVG отображает готовые прямоугольники и линии; viewBox с `preserveAspectRatio="xMidYMid meet"` сохраняет единый масштаб X/Y.
Вершина поворотного треугольника указывает на петли, толстые отметки показывают сторону петель; пунктирный треугольник обозначает откидывание.

Площади в м² определяются отдельно в geometry. Pricing Engine реализует:

```text
(totalArea × basePrice
 + activeArea × basePrice × activityPercent / 100
 + totalArea × basePrice × colorPercent / 100)
 × (1 + productMarkupPercent / 100)
```

Для turn/tilt_turn активна площадь соответствующей нижней секции; fixed и фрамуга неактивны.
Фрамуга имеет всю ширину окна и собственную высоту; нижние секции имеют высоту окна минус высота фрамуги.
Промежуточные величины не округляются, totalMinor хранит итог в копейках RUB.
Отображаемые строки округляются для чтения, поэтому их сумма может отличаться от итога на копейку.
Размеры трактуются как прямоугольная площадь изделия без вычетов профиля, технологических припусков и минимальной оплачиваемой площади.

## Ручная проверка

Сначала «Новый расчёт» → при необходимости заполнить и сохранить данные клиента/объекта → «Добавить замер» → «Окно» или «Отделка окна».
Существующий editor заканчивается кнопкой «Сохранить замер», затем открывается состав расчёта.
«Добавить ещё» возвращает к выбору типа; «Перейти к смете» показывает позиции, subtotal и настройку скидки/итоговой цены.
Для каждого замера доступны «Изменить», «Копировать», «Удалить». Редактирование сохраняет ID; копия получает новый ID и независимые параметры/тарифы.
Сохранение замера, копирование и удаление сразу записывают весь Calculation. Незавершённый ввод editor не сохраняется.

Структура Calculation: `id`, `schemaVersion: 3`, `createdAt`, `updatedAt`, optional `clientName/clientPhone/objectAddress`,
`measurements: (WindowMeasurement | WindowFinishMeasurement | BalconyMeasurement)[]`, `orderAdditionalWorks: AdditionalWork[]`, `configuration[measurementId]`.
Каждый snapshot помечен kind замера и содержит его тарифы. Контейнер не знает конкретных формул.
`estimateMeasurement` делегирует существующим модулям; `MeasurementEstimate = WindowEstimate | FinishEstimate` возвращает geometry и price одного замера.
`estimateCalculation` суммирует целые копейки позиций. Старый schemaVersion=2 в результате одного замера сохранён для адаптера миграции, не является версией нового Calculation.

IndexedDB v3 хранит несколько расчётов и последний открытый ID. После reload автоматически восстанавливается весь выбранный расчёт.
Миграция v2 → v3 превращает каждую старую запись в отдельный одноэлементный Calculation с прежним ID и тарифами.
Исходные записи резервируются в `legacyCalculations`; миграция целиком откатывается при ошибке. Старые v1 проходят сначала через v2.
Отсутствовавшие даты получают время миграции; цены пересчитываются текущими модулями по сохранённым тарифам.
Никакие старые расчёты автоматически не объединяются и не удаляются.

Контроль полного flow: добавить стандартное глухое окно **17 250 ₽** и Simple-отделку **6 780 ₽** — subtotal **24 030 ₽**.
Скопировать окно — subtotal **41 280 ₽**; изменить название копии, убедиться, что оригинал не изменён; удалить копию — снова **24 030 ₽**.
Перезагрузить страницу: оба замера и данные клиента должны сохраниться. Создать второй расчёт и переключиться обратно через список.
Calculation/pricing/geometry не зависят от auth или subscription; будущая проверка доступа принадлежит отдельному Access layer.

Порядок формы: помещение → тип → общие размеры → ширины секций → открывания → профиль → фурнитура → ламинация → текущая цена → сохранить.
Цена и эскиз обновляются автоматически только для валидного ввода.

При выборе single/double/triple создаются равные глухие секции. Изменение общей ширины не перераспределяет секции:
измените их вручную или нажмите «Распределить поровну» (сохраняет открывания/фурнитуру).
При переходе к активному открыванию по умолчанию выбираются петли слева и первая совместимая фурнитура; поля доступны для изменения.
При смене материала выбираются первый совместимый профиль и фурнитура активных секций.
При включении фрамуги высоту нужно задать явно: ноль, отрицательная высота и высота >= общей запрещены.

Равные ширины вычисляются делением без округления. Сумма проверяется с машинным допуском
`8 × Number.EPSILON × max(width, sum)`; реальный размер не корректируется.
Для трети 1000 мм поля содержат полное число JS, а подписи эскиза могут округляться для чтения.
Только превышение активной площади над общей в пределах `32 × Number.EPSILON × totalAreaM2` ограничивается общей площадью после суммирования; размеры не меняются.

Демо-тарифы: 10 000 ₽/м², активность 20%, ламинация 10%/20%, наценка 15%.
Для окна 1000 × 1500 мм общая площадь 1,5 м²:

| Открывание | Ламинация | Итог |
|---|---|---:|
| fixed | нет | 17 250 ₽ |
| turn / tilt_turn | нет | 20 700 ₽ |
| turn / tilt_turn | одна сторона | 22 425 ₽ |
| turn / tilt_turn | две стороны | 24 150 ₽ |

Дополнительный пример: double, 2000 × 1800 мм, секции 700 fixed + 1300 turn,
фрамуга 300 мм, ламинация с одной стороны. Общая площадь 3,6 м², активная 1,95 м²,
итог при демо-тарифах **50 025 ₽**. Смена hingeSide или совместимой фурнитуры не меняет цену.
Для triple можно задать 500 / 700 / 900 мм при общей ширине 2100 мм и проверить реальные пропорции эскиза.

Нажать «Сохранить замер»: откроется состав расчёта. После перезагрузки весь последний открытый расчёт восстанавливается автоматически.
Невалидное изменение скрывает цену/эскиз и блокирует сохранение. Все расчёты доступны в списке «Сохранённые расчёты».
Тарифы включены в снимок Calculation. Настройки выбранных материалов отделки редактируются в форме; отдельного каталога/хранилища конфигурации пока нет.
Данные привязаны к origin браузера (включая порт), не синхронизируются и могут исчезнуть при очистке данных сайта.

## Балконный блок

Порядок: Окно → Балконный блок → количество окон → положение двери → размеры двери → размеры окон
→ открывание каждого элемента → профиль → фурнитура → ламинация → текущая цена → сохранить.

Для одного окна дверь только left/right; для двух также middle. Окна сохраняют свои номера при перемещении двери.
Верхние края всех элементов выровнены; нижние края определяются реальной высотой. Никакой площади под окнами в расчёте нет.
Новые размеры и позиция двери пусты. Новые элементы глухие; при выборе активного открывания петли первоначально слева, фурнитуру нужно выбрать.

Контроль: глухое окно 1400×1500 мм + активная дверь 700×2200 мм дают **3,64 м²** общей и **1,54 м²** активной площади.
С демо-тарифами и без ламинации итог **45 402 ₽**, с односторонней ламинацией — **49 588 ₽**.
Окно должно быть визуально вдвое шире двери; дверь выше окна.
Для двух окон 500/1000 мм, общей высоты окон 1500 мм и двери 700×2200 мм общая площадь **3,79 м²**.
Проверьте все три позиции двери: цена не меняется, второе окно визуально вдвое шире первого.

Переключение 2→1→2 возвращает параметры второго окна, пока открыта страница.
Если при уменьшении количества выбрано middle, цена блокируется до явного выбора допустимой позиции.
Черновики блока и прямоугольного окна сохраняются в памяти при переключении типов; скрытые черновики не записываются в IndexedDB.
Сохраните валидный блок, обновите страницу и откройте «Изменить»: должны восстановиться размеры, дверь, окна, открывания, тарифы и цена.
Блок хранится внутри measurements расчёта v3.

## Отделка окна

«Добавить замер» → «Отделка окна» открывает WindowFinishMeasurement: помещение/название, ширина, высота, глубина,
откосы и/или подоконник, материалы и их настройки, текущая цена, локальное сохранение.
Геометрия и pricing независимы от React и идентичности замера, поэтому могут позже использоваться из flow окна.

`FinishConfiguration = { currency: 'RUB', materials: FinishMaterialConfiguration[] }`.
Материал содержит `id`, `name`, `finishType: slope | sill`, `sizing` и `pricing`:

- sizing: `lengthAllowancePerPieceMm`, `depthAllowanceMm`, `purchaseStepMm`;
- Simple: `materialSellingPricePerM`, `workRatePerM`, необязательные `depthCoefficient` и диапазоны `{ maxDepthMm, coefficient }`;
- Advanced: `materialPurchasePricePerM`, `materialMarkupPercent`, `workRatePerM`, необязательные диапазоны `{ maxDepthMm, purchasePricePerM }`.

Simple нормализуется в общую ставку с нулевой отдельной наценкой. Engine получает только нормализованную конфигурацию.
В Simple база материала означает продажную стоимость, а не известную закупочную себестоимость.
Диапазон выбирается по глубине с припуском, верхняя граница включительна; выход за последний диапазон блокирует расчёт.
Редактор демонстрирует Simple и минимальный Advanced; добавление/удаление диапазонов и каталог материалов не реализованы.

Откосы: верхняя и две боковые детали, установленная длина `widthM + 2 × heightM`.
Подоконник: одна деталь, длина `widthM`. Припуск длины добавляется один раз к каждой детали.
Закупочная кратность применяется к длине КАЖДОЙ детали с припуском отдельно, затем закупочные длины суммируются.
Шаг 0 не округляет. Процент отходов не применяется. Это консервативная модель «каждая деталь отдельно», без оптимизации раскроя.
Контроль без припусков: 1400/2100/2100 мм при шаге 250 мм → 1500/2250/2250 мм, всего **6000 мм**.
Работа оплачивается только по установленной длине, без припусков, закупочного округления и наценки.

Ручная проверка на демонстрационных настройках: 1400×1500 мм, глубина 250 мм.
Откосы 4,4 м, подоконник 1,4 м. Simple: только откосы **4 400 ₽**, только подоконник **2 380 ₽**, оба **6 780 ₽**.
Выберите оба Advanced: с припусками и отдельным округлением деталей — **7 560 ₽** (материалы 5 100 ₽, работа 2 460 ₽).
Изменение наценки или закупочного шага меняет только стоимость материала.
«Сохранить замер» → обновить страницу → «Изменить» восстанавливает размеры, выбор и тарифы отделки в составе расчёта.
При миграции v2 → v3 старые тарифы сохраняются, но geometry и цена пересчитываются по текущей модели. Исходные записи резервируются.
Имя припуска `lengthAllowancePerPieceMm` сохранено, чтобы прежние значения загружались без переименования.

## Вне текущего этапа

Нет CRM, backend, auth, subscriptions, payments, серверного хранения или синхронизации.
Нет отделки балкона, интеграции отделки в flow окна, сложной модели наружной отделки, каталога поставщиков,
DocumentSettings, полноценного документа сметы и экспорта PDF. Папка application/documents резервирует границу будущего сценария.

Тесты покрывают single/double/triple, разные ширины, фрамугу, открывания и петли, совместимость фурнитуры,
границы размеров, пропорции geometry/SVG, неизменность Pricing Engine, сохранение v3 и миграции v1/v2 с откатом ошибок.
Для balconyBlock проверяются пять компоновок, контрольные 3,64 м², активные площади, пропорции, сохранение/загрузка и сохранность параметров черновика.
